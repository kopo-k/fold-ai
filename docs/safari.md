# Safari

Safari uses the same Web Extensions API as Chrome/Firefox, but distribution is
very different: a Safari extension can only ship **bundled inside a macOS / iOS
app**. The `safari/` directory holds that wrapper — an Xcode project generated by
`xcrun safari-web-extension-converter` and committed to the repo.

## Building

macOS + Xcode required.

```bash
pnpm build:safari
```

This builds `dist/` and syncs it into the Xcode project's resources. On the first
run (when `safari/` doesn't exist yet) it generates the Xcode project via the
converter.

> Do not edit the JS/CSS inside the Xcode project by hand — the next
> `pnpm build:safari` overwrites it. Edit source under `src/` instead.

## Running locally (unsigned)

1. Open the generated project in Xcode and run the app target once.
2. In Safari, enable **Settings → Advanced → Show features for web developers**.
3. In the **Developer** menu, enable **Allow Unsigned Extensions**.
4. Enable the extension in **Settings → Extensions**.

## Things that bite you

- **Host permissions are not granted until the user allows them manually.** Treat
  the no-permission state as normal: do nothing and exit quietly. Never show an
  error dialog. (`loadSettings()` falls back to defaults for exactly this reason.)
- **Use only the Promise-based `browser.*` API** (via `webextension-polyfill`).
  Some `chrome.*` callback forms don't exist in Safari.
- **`storage.sync` has tighter size and rate limits.** Keep settings small and
  debounce writes (`storage.ts` already does).
- **Content-script injection can be later than on Chrome.** Don't hard-code a
  `document_idle` assumption — we scan existing DOM _and_ watch with a
  MutationObserver.
- **iOS Safari runs the same extension.** Toggle hit areas are >= 44x44 px; no
  hover-only UI.

## Versioning

`manifest.config.ts` (via `package.json`) is the source of truth. Keep Xcode's
`MARKETING_VERSION` in sync through `pnpm build:safari` — never bump one side
alone.

## App Store

Distribution goes through the App Store, which requires an Apple Developer
Program membership and review. Signing certificates and provisioning profiles are
**never** committed — use GitHub Secrets in CI.
